1. Abstract

The IT Helpdesk and Asset Support Management System is a comprehensive relational database application engineered for enterprise technical support and computing hardware asset lifecycle tracking. Modern organizations frequently suffer from lost helpdesk requests, missing computing assets, unmonitored repair expenses, and absent operational audit trails due to fragmented management tools.

This project delivers a normalized Third Normal Form (3NF) relational database designed in MySQL 8.0+ comprising 14 interconnected tables. The database enforces relational integrity using Primary Keys, Foreign Keys (CASCADE, RESTRICT, SET NULL), UNIQUE constraints, and CHECK expressions. The system features a modern Python backend using parameterized SQL queries and a single-page web interface. Real-time VIEW, INSERT, and DELETE operations are supported with live verification in MySQL. Automated testing confirms 100% compliance across all evaluation criteria.

2. Introduction & Problem Statement

Modern enterprises manage diverse computing assets alongside dozens of daily technical support requests across multiple organizational departments. When managed through spreadsheets or informal channels:

  • Lost Helpdesk Tickets: Tickets lack centralized queuing, causing SLA breaches and neglected users.
  • Technician Accountability Deficit: Unclear technician assignments result in duplicate effort and delayed resolutions.
  • Untracked Hardware Inventory: Relocations, warranty expirations, and device reallocations go unmonitored.
  • Absence of Immutable Audit Trails: State transitions are overwritten rather than historically preserved.
  • Untracked Maintenance Expenditure: Servicing expenses are not correlated with physical assets or departments.

3. System Objectives & Scope

  1. Provide a centralized MySQL relational database in Third Normal Form (3NF).
  2. Support entity inheritance for Incidents (failures) and Service Requests (provisioning).
  3. Catalog hardware assets by unique tag and serial number, linked to user ownership and warranties.
  4. Record immutable audit trails in status_histories for every state transition.
  5. Deliver a live, responsive web user interface connected directly to MySQL for live viva demonstration.

4. Relational Schema & 3NF Normalization

The database schema comprises 14 normalized tables:

  • Organization Domain: departments, users
  • Support Classification: categories, priorities
  • Support Staff: support_staff, assignments
  • Hardware Assets: warranties, assets, maintenance
  • Ticketing & Lifecycles: tickets, incidents, service_requests, status_histories, resolutions

Normalization Proof:

  • 1NF: All attributes contain atomic values; composite/multi-valued attributes are separated into dedicated relations.
  • 2NF: Every non-prime attribute is fully functionally dependent on its respective primary key.
  • 3NF: No non-prime attribute is transitively dependent on a primary key (e.g. departmental locations depend on department_id, not user_id).
